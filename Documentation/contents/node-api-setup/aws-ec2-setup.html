AWS EC2 Node.js + MongoDB Setup

This guide explains how to deploy the FoodBite Node.js API with a self-hosted MongoDB database on AWS EC2.

This setup is suitable for:

  • Testing
  • Demo servers
  • Small to medium production workloads

Architecture Overview

  • Server: AWS EC2 (Ubuntu)
  • Backend: Node.js + Express
  • Database: MongoDB (Self-hosted)
  • Process Manager: PM2
  • Reverse Proxy: Nginx
  • SSL: Let’s Encrypt (Recommended)
  • IP Type: Elastic IP (Recommended)

Step 1: Create an AWS EC2 Instance

  1. Log in to AWS Console
  2. Go to EC2 → Instances
  3. Click Launch Instance

Instance Configuration

  • Name: foodbite-api
  • AMI: Ubuntu Server 22.04 LTS
  • Instance type:
    • Minimum: t2.micro (testing only)
    • Recommended: t3.small (2 GB RAM)

Key Pair

  • Create a new key pair
  • Type: RSA
  • Download .pem file

Network Settings (VERY IMPORTANT)

  • ✅ SSH (22) → Your IP
  • ✅ HTTP (80) → 0.0.0.0/0
  • ✅ HTTPS (443) → 0.0.0.0/0

Click Launch Instance

📌 Note your Public IPv4 address

Step 2: Allocate Elastic IP (RECOMMENDED)

  1. EC2 → Elastic IPs
  2. Allocate Elastic IP
  3. Associate with your EC2 instance

📌 Use this Elastic IP everywhere (DNS, SSH, Nginx)

Connect to Server via SSH

chmod 400 foodbite-key.pem
ssh -i foodbite-key.pem ubuntu@YOUR_ELASTIC_IP

Update Server

sudo apt update && sudo apt upgrade -y

Step 3: Install Node.js (Recommended LTS)

curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs

Verify

node -v
npm -v

Install Yarn via Corepack (Optional)

sudo corepack enable
sudo corepack prepare yarn@stable --activate
yarn -v

Step 4: Install MongoDB (Self-Hosted)

Add MongoDB Repository

curl -fsSL https://pgp.mongodb.com/server-7.0.asc |
sudo gpg --dearmor -o /usr/share/keyrings/mongodb-server-7.0.gpg
echo "deb [signed-by=/usr/share/keyrings/mongodb-server-7.0.gpg] https://repo.mongodb.org/apt/ubuntu jammy/mongodb-org/7.0 multiverse" |
sudo tee /etc/apt/sources.list.d/mongodb-org-7.0.list

Install MongoDB

sudo apt update
sudo apt install -y mongodb-org

Start & Enable

sudo systemctl start mongod
sudo systemctl enable mongod
mongosh

Step 5: Secure MongoDB (IMPORTANT)

sudo nano /etc/mongod.conf
bindIp: 127.0.0.1
sudo systemctl restart mongod

Create Admin User

mongosh
use admin
db.createUser({
  user: "foodbiteAdmin",
  pwd: "STRONG_PASSWORD",
  roles: [{ role: "root", db: "admin" }]
})

⚠️ Avoid special characters:

@ : / ? # [ ] % &

Enable Authentication

sudo nano /etc/mongod.conf
security:
  authorization: enabled
sudo systemctl restart mongod

Step 6: Upload FoodBite Node.js API (Private GitHub Repository)

This step explains how to push your API to a private GitHub repository and clone it securely using a Personal Access Token (PAT).

6.1 Install Git

sudo apt install git -y
git --version

6.2 Create Private Repository

  • Name: foodbite-api-aws-ec2
  • Visibility: Private
  • Do NOT initialize with README

6.3 Generate GitHub PAT

  • Scopes: repo
  • Expiration: 30 / 90 days

6.4 Push Code

git init
git add .
git commit -m "Initial FoodBite API commit"
git remote add origin https://github.com/YOUR_USERNAME/foodbite-api-aws-ec2.git
git push https://YOUR_USERNAME:YOUR_GITHUB_TOKEN@github.com/YOUR_USERNAME/foodbite-api-aws-ec2.git main

6.5 Clone on Server

git clone https://github.com/YOUR_USERNAME/foodbite-api-aws-ec2.git
cd foodbite-api-aws-ec2

6.6 Remove Token

git remote set-url origin https://github.com/YOUR_USERNAME/foodbite-api-aws-ec2.git
git remote -v

Install Dependencies

npm install

Step 7: Configure Environment Variables

cp .env.example .env
nano .env
PORT=3000
NODE_ENV=production

MONGODB_URL=mongodb://foodbiteAdmin:STRONG_PASSWORD@127.0.0.1:27017/foodbite?authSource=admin

JWT_SECRET=your_secret_key

Step 8: Run API with PM2

If you plan to use Push Notifications or Firebase-based services, you must configure Firebase Admin SDK.

Important:
  • Place your Firebase service account JSON file inside: API/src/fcm_keys/serviceAccountKey.json
  • This file is required for Firebase Admin (push notifications).
  • You may commit this file only if your repository is private.
  • If you do not want to configure Firebase now, you can safely comment out or skip Firebase Admin initialization in: src/app.js
  • The API will still run normally without Firebase for local testing.
Documentation Reference:

Step-by-step instructions for generating the Firebase service account JSON are available here:

Firebase Service Account JSON Guide

Please follow this guide to generate and configure the service account correctly.

Install PM2:

sudo npm install -g pm2

Start API:

yarn start

or

npm start

Save process:

pm2 save
pm2 startup

Step 9: Setup Nginx Reverse Proxy

Install Nginx:

sudo apt install nginx -y

Create config:

sudo nano /etc/nginx/sites-available/foodbite
server {
    listen 80;
    server_name YOUR_DOMAIN_OR_ELASTIC_IP;

    location /storage/ {
       alias /your_node_api_absolute_path/public/;

       access_log off;
       expires 1y;

       # ✅ ADD THIS (CORS FIX)
       add_header Access-Control-Allow-Origin *;
       add_header Access-Control-Allow-Methods "GET, OPTIONS";
       add_header Access-Control-Allow-Headers "*";
    }

    location / {
        proxy_pass http://localhost:3000;

        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

        proxy_read_timeout 60s;
        proxy_send_timeout 60s;
    }
}

Enable site:

sudo ln -s /etc/nginx/sites-available/foodbite /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl restart nginx

Test API On IP Address

This guide explains how to connect your Namecheap domain to DigitalOcean and secure your Node.js API with a free Let’s Encrypt SSL certificate.

Step 10: Point Namecheap Domain to DigitalOcean

10.1 Get Your Server IP

From your AWS EC2, note down your public IP:

YOUR_SERVER_IP

10.2 Login to Namecheap

  1. Go to Namecheap Dashboard
  2. Open Domain List
  3. Click Manage on YOUR_DOMAIN_NAME.COM
  4. Navigate to Advanced DNS

10.3 Add / Update DNS Records

A Record (Root Domain)

Type Host Value TTL
A @ YOUR_SERVER_IP Automatic

A Record (WWW)

Type Host Value TTL
A www YOUR_SERVER_IP Automatic

❌ Remove any parking, URL redirect, or old A records

10.4 Wait for DNS Propagation

DNS usually updates within 1–10 minutes.

Verify:

ping YOUR_DOMAIN_NAME.COM

If it resolves correctly, continue to the next step.

Step 11: Update Nginx Domain Configuration

Edit your Nginx config file:

sudo nano /etc/nginx/sites-available/foodbite

Update the server_name:

server_name YOUR_DOMAIN_NAME.COM www.YOUR_DOMAIN_NAME.COM;

Test and reload Nginx:

sudo nginx -t
sudo systemctl reload nginx

Test in browser:

http://YOUR_DOMAIN_NAME.COM

✔ Your API should be accessible

Step 12: Install Free SSL (Let’s Encrypt)

12.1 Install Certbot

sudo apt update
sudo apt install certbot python3-certbot-nginx -y

12.2 Generate SSL Certificate

sudo certbot --nginx -d YOUR_DOMAIN_NAME.COM -d www.YOUR_DOMAIN_NAME.COM

During prompts:

  • Enter your email
  • Agree to terms → Y
  • Redirect HTTP to HTTPS → 2 (Recommended)

12.3 Verify Auto-Renewal

sudo certbot renew --dry-run

✔ SSL auto-renews every 90 days

Step 13: Final Nginx Configuration (SSL + Socket.IO)

Certbot updates Nginx automatically. Your final configuration should look like this:

server {
    listen 443 ssl;
    server_name YOUR_DOMAIN_NAME.COM www.YOUR_DOMAIN_NAME.COM;

    ssl_certificate /etc/letsencrypt/live/YOUR_DOMAIN_NAME.COM/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/YOUR_DOMAIN_NAME.COM/privkey.pem;

    location /storage/ {
       alias /your_node_api_absolute_path/public/;

       access_log off;
       expires 1y;

       # ✅ ADD THIS (CORS FIX)
       add_header Access-Control-Allow-Origin *;
       add_header Access-Control-Allow-Methods "GET, OPTIONS";
       add_header Access-Control-Allow-Headers "*";
    }

    location / {
        proxy_pass http://localhost:3000;

        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

        proxy_read_timeout 60s;
        proxy_send_timeout 60s;
    }
}

server {
    listen 80;
    server_name YOUR_DOMAIN_NAME.COM www.YOUR_DOMAIN_NAME.COM;
    return 301 https://$host$request_uri;
}

Reload Nginx:

sudo systemctl reload nginx

Step 14: Final Verification Checklist

  • ✔ https://YOUR_DOMAIN_NAME.COM opens
  • ✔ SSL padlock visible 🔒
  • ✔ PM2 app running
  • ✔ certbot renew works

❌ Common Namecheap + SSL Mistakes

  • Using Namecheap URL Redirect
  • DNS not fully propagated
  • Domain mismatch in server_name
  • Port 80 or 443 blocked
  • Forgetting to reload Nginx

🎯 You’re Now Production-Ready

Your setup now supports:

  • ✅ HTTPS
  • ✅ Secure APIs
  • ✅ Free auto-renew SSL

Configure CLIENT_ORIGINS (CORS Setup)

If your frontend (Angular / Web / Admin Panel) cannot connect to your API or shows CORS errors, you need to properly configure:

CLIENT_ORIGINS defines which domains are allowed to access your API.

👉 Example:

  • Frontend (Admin Panel):

    https://foodbite.elitecanyon.com

  • Backend (API):

    https://foodbite-api.elitecanyon.com

Since these are different domains → CORS is required

❗ Common Error

If not configured correctly, you may see:

  • ❌ Blocked by CORS policy
  • ❌ No 'Access-Control-Allow-Origin' header
  • ❌ API works in Postman but not in browser

⚙️ Step 1: Open .env File

Go to your project directory:

pwd

Example:

/home/foodbite-api

Then open .env:

✏️ Step 2: Set CLIENT_ORIGINS

Add your frontend domain:

CLIENT_ORIGINS=https://foodbite.elitecanyon.com

If you have multiple frontends (admin, website, etc.), separate them using commas:

CLIENT_ORIGINS=https://foodbite.elitecanyon.com,https://yourwebsite.com,http://localhost:4200

Important Rules

  • Do NOT add trailing slash /
  • Do NOT add spaces between URLs
  • Use full protocol (http:// or https://)

🔄 Step 3: Restart Server

After updating .env, restart your Node.js app:

pm2 restart all

🧪 Step 4: Test

Open your frontend and check API calls.

👉 You can also verify using browser DevTools:

  • Network tab
  • Check request headers
  • Confirm Access-Control-Allow-Origin
