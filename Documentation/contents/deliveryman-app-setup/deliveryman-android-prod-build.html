Android Prod Build (Android Studio)

This guide explains how to generate production-ready Android release builds (APK and AAB) for the FoodBite Deliveryman App using Android Studio.

This method is recommended if you prefer a GUI-based workflow instead of CLI.

✅ Prerequisites

Before generating the production build, ensure that:

  • Flutter & Android Studio are installed
  • Deliveryman App setup is completed
  • Firebase & Google Maps are configured
  • API base URL points to production
  • Android package name is finalized
  • Release keystore is available

1️⃣ Open Android Module in Android Studio

From the Flutter project root:

  • Open Android Studio
  • Click Open
  • Select the android/ folder inside the Flutter project

Android Studio will sync Gradle automatically.

2️⃣ Configure Release Keystore

Ensure the keystore is already configured.

Keystore File Location
android/app/foodbite_deliveryman.jks

3️⃣ Generate Release APK (Android Studio)

In Android Studio, follow these steps:

  1. Open the top menu and navigate to:
    Build → Build Bundle(s) / APK(s) → Build APK(s)
  2. Wait for the build process to complete
  3. When prompted, click Locate to view the generated APK file

📁 Output Path:

android/app/build/outputs/apk/release/app-release.apk

4️⃣ Generate Release App Bundle (AAB)

In Android Studio, follow these steps:

  1. Open the top menu and navigate to:
    Build → Build Bundle(s) / APK(s) → Build Bundle(s)
  2. Wait for the build process to complete
  3. When prompted, click Locate to view the generated AAB file

📁 Output Path:

android/app/build/outputs/bundle/release/app-release.aab

✅ AAB is mandatory for Google Play Store submission.

5️⃣ Verify Release Build

(Optional but recommended)

Before uploading your FoodBite Deliveryman App production build to the Google Play Store, make sure to test it thoroughly on a local device. Here's a checklist:

  • Install Release APK on Real Device
    Test the actual release build, not just debug builds.
  • Test All Firebase Features
    • Push notifications
    • Authentication (Login / Signup)
    • Firestore / Realtime Database operations
  • Test Google Maps Functionality
    • Location tracking
    • Directions & distance calculations
    • Markers & map UI
  • Test Payment Integrations
    Ensure all payment flows work correctly with your production API keys.
  • Check API Connectivity
    • Base URL points to production server
    • All endpoints respond correctly
    • Error handling works as expected
  • Test Offline / Network Error Handling
    Ensure app behaves gracefully without internet or on slow connections.
  • Check Push Notifications
    Verify that notifications are received correctly on the device.
  • Check Background Services
    Any background tasks (like scheduled orders) should run correctly.
  • Validate App Permissions
    Location, storage, camera, notifications, etc.
  • Test App Version & Build Number
    Ensure version increments are correctly reflected.
  • Stress Test Key Flows
    • Order placement
    • Cart operations
    • Profile updates
  • Check for UI / Layout Issues
    Test on multiple screen sizes and orientations.
  • Run flutter doctor
    Verify Flutter environment is healthy and dependencies are resolved.
Testing thoroughly on real devices ensures that native features like payments, push notifications, and Google Maps work correctly before submitting to the Play Store.

6️⃣ Update App Version & Build Number via local.properties

You can change the app version and build number directly in the android/local.properties file.

Open:

android/local.properties

Locate or add the following lines:

flutter.versionName=1.0.0
flutter.versionCode=1
  • flutter.versionName → App version visible to users (e.g., 1.0.0, 1.1.0)
  • flutter.versionCode → Build number (must be incremented for every Play Store upload)

Example for a new version:

flutter.versionName=1.1.0
flutter.versionCode=2

⚠️ Make sure to increment the flutter.versionCode for every new release; otherwise, Google Play will reject the upload.

Flutter Web builds do not support: Google Maps native features, Payments, Push notifications. Always test production builds on a real Android device.
