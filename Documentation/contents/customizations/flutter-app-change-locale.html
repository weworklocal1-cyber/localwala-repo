Add or Update App Languages (Flutter)

Add new languages or update existing translations in FoodBite Flutter applications (Customer, Delivery Partner, Kitchen, Waiter, Restaurant) using ARB locale files.

🌐 Change Default Language (Required)

Update the default app language in the centralized environment configuration:

lib/app/env.dart

Example:

static const String defaultLanguage = 'en'; // English
static const String defaultLanguage = 'es'; // Spanish
static const String defaultLanguage = 'hi'; // Hindi
static const String defaultLanguage = 'ar'; // Arabic

📁 Localization Directory

All language files are located at:

lib/app/l10n/

Example structure:

lib/app/l10n/
├── app_en.arb
├── app_hi.arb
├── app_fr.arb

🗂️ ARB File Structure

ARB files use key-value pairs for translations.

Example: app_en.arb

{
  "appName": "FoodBite",
  "login": "Login",
  "welcomeUser": "Welcome ##dynamic##",
  "orderCount": "You have ##dynamic## orders"
}

🔑 Translation keys must be identical across all locale files.

➕ Add a New Language

Example: Adding French

1️⃣ Create a new locale file
lib/app/l10n/app_fr.arb
2️⃣ Add translations
{
  "appName": "FoodBite",
  "login": "Connexion",
  "welcomeUser": "Bienvenue ##dynamic##",
  "orderCount": "Vous avez ##dynamic## commandes"
}

📝 Register Supported Languages

After adding new locale files, register the language inside env.dart:

static const supportedLanguages = [
  Locale('en'),
  Locale('ar'),
  Locale('hi'),
  Locale('es'),
];

⚠️ The locale code must match the `.arb` filename.

🌍 Language Selector Configuration (UI)

FoodBite uses a structured model to control:

  • Language name
  • Locale code
  • Flag images
  • Descriptions
  • Button text

Example entry:

LanguageEntityModel(
  code: 'es',
  value: 'Español',
  locale: 'es_ES',
  title: 'Seleccionar idioma',
  activeImage: 'assets/images/languages/spanish-active.png',
  deactiveImage: 'assets/images/languages/spanish-deactive.png',
  description:
      "Seleccione su idioma preferido para disfrutar de una experiencia perfecta con nuestra aplicación de entrega de alimentos.",
  selectText: 'Selecciónelo',
),

✏️ Update Existing Translations

  1. Open the relevant `.arb` file
  2. Update only the text value
  3. Do not change the key
  4. Save the file
Dynamic Content Rules (Important)

Do NOT change placeholders like ##dynamic##:

"welcomeUser": "Welcome ##dynamic##"  // Correct
"welcomeUser": "Bienvenue ##dynamic##"  // Correct translation

🧩 Using Translations in UI

Text(AppLocalizations.of(context)!.welcomeUser(userName));

🔄 Apply Changes

flutter clean
flutter pub get
flutter run

🧪 Testing Languages

Test via Device Settings
  • Change the system language
  • Restart the app
Force a Locale (for testing only)
locale: const Locale('fr'),

✅ Verification Checklist

  • ✅ New locale file added under lib/app/l10n
  • ✅ Translation keys match existing languages
  • ✅ Dynamic placeholders remain unchanged
  • ✅ App displays translated text correctly
  • ✅ No missing or broken strings
Important Notes:
  • English (app_en.arb) should always be kept as the base language
  • Do not hardcode UI text outside localization files
  • Missing keys may cause fallback or blank text
  • Keep translations short to avoid UI overflow
