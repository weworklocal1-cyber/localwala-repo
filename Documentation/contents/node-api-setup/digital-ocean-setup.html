DigitalOcean Node.js + MongoDB Setup

Deploy FoodBite Node.js API with self-hosted MongoDB on DigitalOcean

This guide explains how to deploy the FoodBite Node.js API with a self-hosted MongoDB database on a DigitalOcean Droplet.

This setup is suitable for:

  • Testing
  • Demo servers
  • Small to medium production workloads

Architecture Overview

  • Server: DigitalOcean Droplet (Ubuntu)
  • Backend: Node.js + Express
  • Database: MongoDB (Self-hosted)
  • Process Manager: PM2
  • Reverse Proxy: Nginx
  • SSL: Let’s Encrypt (Recommended)

Step 1: Create a DigitalOcean Droplet

  1. Login to DigitalOcean Dashboard
  2. Click Create → Droplets
  3. Select:
    • Image: Ubuntu 22.04 LTS
    • Plan: Basic
    • CPU: Regular
    • Size: 1GB RAM (Minimum), 2GB RAM (Recommended)
  4. Authentication: SSH Key (Recommended) or Password
  5. Click Create Droplet
Note your server public IP address.

Step 2: Connect to Server via SSH

ssh root@YOUR_SERVER_IP
apt update && apt upgrade -y

Step 3: Install Node.js (LTS)

curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt install -y nodejs
node -v
npm -v

Install Yarn (Optional)

corepack enable
corepack prepare yarn@stable --activate
yarn -v

Step 4: Install MongoDB (Self-Hosted)

curl -fsSL https://pgp.mongodb.com/server-7.0.asc | \
gpg --dearmor -o /usr/share/keyrings/mongodb-server-7.0.gpg
echo "deb [signed-by=/usr/share/keyrings/mongodb-server-7.0.gpg] \
https://repo.mongodb.org/apt/ubuntu jammy/mongodb-org/7.0 multiverse" \
| tee /etc/apt/sources.list.d/mongodb-org-7.0.list
apt update
apt install -y mongodb-org
systemctl start mongod
systemctl enable mongod
mongosh

Step 5: Secure MongoDB

nano /etc/mongod.conf
bindIp: 127.0.0.1
systemctl restart mongod

Create Admin User

mongosh
use admin
db.createUser({
  user: "foodbiteAdmin",
  pwd: "STRONG_PASSWORD",
  roles: [{ role: "root", db: "admin" }]
})
Avoid special characters in MongoDB passwords: @ : / ? # [ ] % & 
security:
  authorization: enabled
systemctl restart mongod

Step 6: Upload FoodBite Node.js API (Private GitHub Repository)

This step explains how to push your FoodBite Node.js API to a private GitHub repository and clone it securely on your server using a Personal Access Token (PAT).

6.1 Install Git on Server

apt install git -y

Verify installation:

git --version

6.2 Create a Private Repository on GitHub

  1. Go to GitHub → New Repository
  2. Repository name: foodbite-api
  3. Visibility: Private
  4. Do NOT initialize with README
  5. Click Create Repository

6.3 Generate GitHub Personal Access Token (PAT)

  1. Go to GitHub → Settings
  2. Open Developer settings
  3. Select Personal access tokens
  4. Tokens (classic) → Generate new token

Select scopes:

  • ✅ repo (full control of private repositories)

Set expiration (recommended):

  • 30 / 90 days

Click Generate token
⚠️ Copy the token immediately (you won’t see it again)

Never share your Personal Access Token publicly.

6.4 Push Local Code to Private Repository (From Your Local Machine)

Inside your FoodBite API project:

git init
git add .
git commit -m "Initial FoodBite API commit"

Add private repository remote:

git remote add origin https://github.com/YOUR_USERNAME/foodbite-api.git

Push using token:

git push https://YOUR_USERNAME:YOUR_GITHUB_TOKEN@github.com/YOUR_USERNAME/foodbite-api.git main

📌 Replace:

  • YOUR_USERNAME
  • YOUR_GITHUB_TOKEN

6.5 Clone Private Repository on Server (Using PAT)

On your DigitalOcean server:

mkdir -p /var/www
cd /var/www
git clone https://github.com/YOUR_USERNAME/foodbite-api.git
cd foodbite-api

6.6 Prevent Token from Being Saved in Plain Text (IMPORTANT)

After cloning, remove token from remote URL:

git remote set-url origin https://github.com/YOUR_USERNAME/foodbite-api.git

Verify:

git remote -v
Leaving a token in the Git remote URL is a security risk.

6.7 Pull Updates in Future (Private Repo)

When updating code on server:

git pull

If prompted:

  • Username → GitHub username
  • Password → Personal Access Token (NOT GitHub password)

6.8 Cache Credentials Securely on Server (Optional)

git config --global credential.helper store
Use this only on trusted private servers.

Common Mistakes (Avoid These)

  • ❌ Using GitHub password instead of PAT
  • ❌ Forgetting repo permission
  • ❌ Committing .env file
  • ❌ Leaving token in git remote -v

Recommended for Production

Method Use Case
SSH keys Best & most secure
Access Token Fast setup, private repos
GitHub Actions Auto-deploy
Your FoodBite API is now safely stored and deployed from a private GitHub repository 🔐🚀

Install Dependencies

npm install

Step 7: Configure Environment Variables

cp .env.example .env
nano .env
PORT=3000
NODE_ENV=production

MONGODB_URL=mongodb://foodbiteAdmin:STRONG_PASSWORD@127.0.0.1:27017/foodbite?authSource=admin
JWT_SECRET=your_secret_key

Step 8: Run API with PM2

If you plan to use Push Notifications or Firebase-based services, you must configure the Firebase Admin SDK.

Important
  • Place your Firebase service account JSON file inside: API/src/fcm_keys/serviceAccountKey.json
  • This file is required for Firebase Admin (push notifications).
  • You may commit this file only if your repository is private.
  • If you do not want to configure Firebase now, you can safely comment out or skip Firebase Admin initialization in: src/app.js
  • The API will still run normally without Firebase for local testing.
Documentation Reference
Step-by-step instructions for generating the Firebase service account JSON are available here:
Firebase Service Account JSON Guide
Please follow this guide to generate and configure the service account correctly.

Install PM2

npm install -g pm2

Start API

yarn start

or

npm start

Save PM2 Process

pm2 save
pm2 startup

Step 9: Setup Nginx Reverse Proxy

Install Nginx

apt install nginx -y

Create Nginx Configuration

nano /etc/nginx/sites-available/foodbite
server {
    listen 80;
    server_name YOUR_DOMAIN_OR_IP;

    location /storage/ {
       alias /your_node_api_absolute_path/public/;

       access_log off;
       expires 1y;

       # ✅ ADD THIS (CORS FIX)
       add_header Access-Control-Allow-Origin *;
       add_header Access-Control-Allow-Methods "GET, OPTIONS";
       add_header Access-Control-Allow-Headers "*";
    }

    location / {
        proxy_pass http://localhost:3000;

        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

        proxy_read_timeout 60s;
        proxy_send_timeout 60s;
    }
}

Enable Site

ln -s /etc/nginx/sites-available/foodbite /etc/nginx/sites-enabled/
nginx -t
systemctl restart nginx

Open Required Firewall Ports

ufw allow OpenSSH
ufw allow 'Nginx Full'
ufw enable

Test API on Server IP Address

This guide explains how to connect your Namecheap domain to DigitalOcean and secure your Node.js API with a free Let’s Encrypt SSL certificate.

Step 10: Point Namecheap Domain to DigitalOcean

10.1 Get Your Server IP

From your DigitalOcean Droplet, note down your public IP:

YOUR_SERVER_IP

10.2 Login to Namecheap

  1. Go to Namecheap Dashboard
  2. Open Domain List
  3. Click Manage on YOUR_DOMAIN_NAME.COM
  4. Navigate to Advanced DNS

10.3 Add / Update DNS Records

A Record (Root Domain)

Type Host Value TTL
A @ YOUR_SERVER_IP Automatic

A Record (WWW)

Type Host Value TTL
A www YOUR_SERVER_IP Automatic

❌ Remove any parking, URL redirect, or old A records

10.4 Wait for DNS Propagation

DNS usually updates within 1–10 minutes.

ping YOUR_DOMAIN_NAME.COM

If it resolves correctly, continue to the next step.

Step 11: Update Nginx Domain Configuration

nano /etc/nginx/sites-available/foodbite
server_name YOUR_DOMAIN_NAME.COM www.YOUR_DOMAIN_NAME.COM;
nginx -t
systemctl reload nginx
http://YOUR_DOMAIN_NAME.COM

✔ Your API should be accessible

Step 12: Install Free SSL (Let’s Encrypt)

12.1 Install Certbot

apt update
apt install certbot python3-certbot-nginx -y

12.2 Generate SSL Certificate

certbot --nginx -d YOUR_DOMAIN_NAME.COM -d www.YOUR_DOMAIN_NAME.COM
  • Enter your email
  • Agree to terms → Y
  • Redirect HTTP to HTTPS → 2 (Recommended)

12.3 Verify Auto-Renewal

certbot renew --dry-run

✔ SSL auto-renews every 90 days

Step 13: Final Nginx Configuration (SSL + Socket.IO)

server {
    listen 443 ssl;
    server_name YOUR_DOMAIN_NAME.COM www.YOUR_DOMAIN_NAME.COM;

    ssl_certificate /etc/letsencrypt/live/YOUR_DOMAIN_NAME.COM/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/YOUR_DOMAIN_NAME.COM/privkey.pem;

    location /storage/ {
       alias /your_node_api_absolute_path/public/;

       access_log off;
       expires 1y;

       # ✅ ADD THIS (CORS FIX)
       add_header Access-Control-Allow-Origin *;
       add_header Access-Control-Allow-Methods "GET, OPTIONS";
       add_header Access-Control-Allow-Headers "*";
    }

    location / {
        proxy_pass http://localhost:3000;

        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

        proxy_read_timeout 60s;
        proxy_send_timeout 60s;
    }
}

server {
    listen 80;
    server_name YOUR_DOMAIN_NAME.COM www.YOUR_DOMAIN_NAME.COM;
    return 301 https://$host$request_uri;
}
systemctl reload nginx

Step 14: Open Firewall Port

ufw allow 443
ufw reload

SSH Key Setup (macOS, Windows, Linux)

Below are real, OS-specific, copy-paste ready steps to create and add an SSH key for macOS, Windows, and Linux.

Configure CLIENT_ORIGINS (CORS Setup)

If your frontend (Angular / Web / Admin Panel) cannot connect to your API or shows CORS errors, you need to properly configure:

CLIENT_ORIGINS defines which domains are allowed to access your API.

👉 Example:

  • Frontend (Admin Panel):

    https://foodbite.elitecanyon.com

  • Backend (API):

    https://foodbite-api.elitecanyon.com

Since these are different domains → CORS is required

❗ Common Error

If not configured correctly, you may see:

  • ❌ Blocked by CORS policy
  • ❌ No 'Access-Control-Allow-Origin' header
  • ❌ API works in Postman but not in browser

⚙️ Step 1: Open .env File

Go to your project directory:

pwd

Example:

/home/foodbite-api

Then open .env:

✏️ Step 2: Set CLIENT_ORIGINS

Add your frontend domain:

CLIENT_ORIGINS=https://foodbite.elitecanyon.com

If you have multiple frontends (admin, website, etc.), separate them using commas:

CLIENT_ORIGINS=https://foodbite.elitecanyon.com,https://yourwebsite.com,http://localhost:4200

Important Rules

  • Do NOT add trailing slash /
  • Do NOT add spaces between URLs
  • Use full protocol (http:// or https://)

🔄 Step 3: Restart Server

After updating .env, restart your Node.js app:

pm2 restart all

🧪 Step 4: Test

Open your frontend and check API calls.

👉 You can also verify using browser DevTools:

  • Network tab
  • Check request headers
  • Confirm Access-Control-Allow-Origin
