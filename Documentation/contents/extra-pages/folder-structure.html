Folder Structure

After purchasing the FoodBite product from CodeCanyon, you will receive a compressed file named:

AppSourceCode.zip

Once extracted, you will see the following folder structure:

AppSourceCode/
├── Admin_panel
├── API
├── Customer_app
├── Deliveryman_app
├── Kitchen_app
├── Restaurant_app
├── Resource
├── Waiter_app
└── documentation.html

API (Node.js Backend)

The API folder contains the complete Node.js backend for FoodBite, including configuration, source code, testing, and deployment files. 

API/
├── bin/
├── logs/
├── public/
├── src/
├── tests/
├── .env.example
├── Dockerfile
├── ecosystem.config.json
├── jest.config.js
├── package.json
├── package-lock.json
├── yarn.lock
└── README

Folder Overview

src/

Main application source code:

  • Routes
  • Controllers
  • Models
  • Services
  • Middlewares

bin/

Startup and executable scripts used to run the server.

public/

Publicly accessible files such as uploaded images and static assets.

tests/

Unit and integration tests for APIs and services.

logs/

Application and error logs for debugging and monitoring.

During development, you will mostly work inside the src/ folder.
Do NOT commit your .env file to version control. Always use .env.example as reference.

Flutter Applications

FoodBite includes multiple Flutter apps sharing a similar architecture.

Common Structure

app_name
├── android
├── ios
├── assets
├── lib
│   ├── app
│   ├── firebase_options.dart
│   └── main.dart
├── pubspec.yaml
└── README.md

lib/app/ contains:

  • core – shared utilities
  • env.dart – environment config
  • l10n – localization
  • presentation – UI screens
  • router – navigation
  • services – API & logic

This structure applies to:

  • Customer App
  • Deliveryman App
  • Restaurant App
  • Kitchen App
  • Waiter App

Resource Folder

The Resource folder contains materials to test and understand the FoodBite API quickly. 

Resource
├── postman_collection.html
└── postman_collection.json

Postman API Collection

  • Authentication APIs
  • User & Role Management
  • Restaurant & Menu Management
  • Order & Payment APIs
  • Delivery & Status APIs

postman_collection.json

Import directly into Postman to test APIs.

postman_collection.html

Open in browser to view API documentation.

It is recommended to test APIs using Postman before running frontend applications.
Postman collection is for local testing only. Always secure production APIs.
