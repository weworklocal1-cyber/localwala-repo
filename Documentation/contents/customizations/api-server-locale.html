Server API Translations

Manage server-side translations for invoices, order summaries, bookings, and tiffin modules in FoodBite APIs

FoodBite APIs support server-level translations for dynamic content such as:

  • Invoices & PDFs
  • Order summaries
  • Booking details
  • Tiffin subscriptions
  • System-generated labels

These translations are used when content is generated on the server, independent of mobile or admin UI translations.

📁 Translation File Location

All server-side translations are defined in:

API/src/utils/translate.js

🧩 Translation Structure

Translations are organized by language code, with nested objects for different modules.

Example Structure

✏️ Update Existing Translations

  1. Open translate.js
  2. Navigate to the required language and module
  3. Update only the string value
  4. Do not change the key names

⚠️ Direction Handling (RTL / LTR)

Each language must define its text direction:

direction: "ltr"; // Left-to-Right
direction: "rtl"; // Right-to-Left (Arabic)

Example for Arabic:

ar: {
  direction: 'rtl',
  orderSummary: {
    orderSummaryKey: 'ملخص الطلب',
  },
},

⚠️ Important Asset Naming Rule

  • ❌ Do NOT rename keys
  • ❌ Do NOT remove existing keys
  • ❌ Do NOT translate object names
  • ❌ Do NOT change structure

Keys are tightly coupled with:

  • Invoice templates
  • PDF generators
  • Booking & tiffin services

Breaking keys may cause runtime crashes or blank documents.

🔄 Apply Changes

After updating server translations:

pm2 restart all

or for development:

npm run dev

Verification Checklist

  • Correct language text appears in invoices
  • Order summaries render properly
  • Booking and tiffin documents show correct labels
  • RTL languages align correctly
  • No missing or undefined labels
Common Mistakes to Avoid
  • Missing translation keys in new languages
  • Inconsistent structure between languages
  • Forgetting to set direction
  • Restart not performed after changes
  • Mixing UI and API translation logic
